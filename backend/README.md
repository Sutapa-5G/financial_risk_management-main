# Risk Navigator — Backend & ML Service

A FastAPI service that replaces the frontend's hardcoded mock data
(`src/data/portfolio.ts`, `src/lib/scoring.ts`) with a real, trained
credit-risk model: a monotonic-constrained gradient-boosted classifier
(`HistGradientBoostingClassifier`) for probability of default, with SHAP
feature attribution, evaluated against a logistic-regression baseline.

## Why the ML is "real" and not just a wrapper

- **Model**: trained on a synthetic-but-realistic borrower population
  (`app/ml/dataset.py`) with a held-out test set — not a hand-coded formula.
  No licensed credit dataset ships with this repo; swap the dataset loader
  for Lending Club / Home Credit / your own data when you have it (the
  training script is the only place that needs to change).
- **Evaluation**: AUC-ROC, precision/recall/F1, KS statistic, a full ROC
  curve, confusion matrix, and a calibration-by-decile table are all
  computed from actual hold-out predictions in `app/ml/train.py`, not
  invented numbers.
- **Explainability**: `/api/score` returns real SHAP values (`shap.TreeExplainer`)
  for each prediction, matching the "SHAP-style feature importance" the
  frontend design brief called for. Falls back to an occlusion-based local
  sensitivity if `shap` isn't installed, so the API still runs.
- **Stress testing**: `/api/stress-test` re-scores the entire portfolio with
  the trained model under shocked DTI / utilization / interest-rate
  assumptions — a genuine what-if simulation, not a fudge factor.
- **Decision threshold** is chosen via Youden's J statistic on the ROC curve
  (not a fixed 0.5), because the simulated default rate is realistically low
  (~4-5%) and a naive threshold would produce near-zero recall.

## Documented simplifications (call these out if this is a resume project)

- **LGD** is a simple function of credit utilization (`app/ml/model.py:estimate_lgd`)
  rather than its own model — a full build would fit a separate LGD
  regression (or a two-stage Tobit/beta model) on recovery data.
- **Portfolio history** (`/api/portfolio/trend`) is a simulated trailing
  12-month aggregation around the book's current model-implied default
  rate, since the demo portfolio doesn't carry real longitudinal scoring
  history. Replace with a real time-series query once loans are scored over
  time.
- **Unexpected loss** in the tier breakdown is approximated as `1.9 ×
  expected loss` rather than a full Basel asset-correlation formula.

## Project layout

```
backend/
  app/
    main.py                  # FastAPI app, CORS, router registration
    config.py                 # settings (CORS origins)
    schemas.py                 # Pydantic models (camelCase over the wire)
    ml/
      dataset.py                # synthetic borrower + default-label generator
      train.py                   # trains the model, writes /artifacts
      model.py                    # loads model, predicts, SHAP explain
    api/
      portfolio.py                 # /api/portfolio/*
      scoring.py                    # POST /api/score
      model_perf.py                  # /api/model/*
      stress.py                       # POST /api/stress-test
    data_store/
      portfolio_store.py              # in-memory demo loan book, scored by the real model
  artifacts/                     # generated by train.py (git-ignored)
    pd_model.joblib
    shap_background.joblib
    metrics.json
  requirements.txt
```

## Setup

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 1. Train the model (writes artifacts/pd_model.joblib + metrics.json)
python -m app.ml.train

# 2. Run the API
uvicorn app.main:app --reload --port 8000
```

Visit `http://localhost:8000/docs` for interactive Swagger docs of every
endpoint below.

**Re-run `python -m app.ml.train` any time** you change `app/ml/dataset.py`
or model hyperparameters — the API refuses to start if `artifacts/` is
missing (see `lifespan` in `app/main.py`).

## API surface (matches the frontend's TypeScript types field-for-field)

| Endpoint | Frontend consumer | Replaces |
|---|---|---|
| `GET /api/portfolio/summary` | Overview KPI cards | `PORTFOLIO_VALUE`, `OVERALL_PD`, `TOTAL_EXPECTED_LOSS`, `AVG_RISK_SCORE` |
| `GET /api/portfolio/trend` | Overview default-rate chart | `DEFAULT_RATE_TREND` |
| `GET /api/portfolio/tier-breakdown` | Overview donut + Portfolio Analytics stacked bar | `TIER_BREAKDOWN` |
| `GET /api/portfolio/recent?limit=8` | Overview recent activity table | `RECENT_APPLICATIONS` |
| `GET /api/portfolio/loans?tier=&status=&min_amount=&max_amount=&sort_by=&sort_dir=&page=&page_size=` | Portfolio Analytics table | `LOANS` |
| `POST /api/score` | Risk Scoring page | `scoreBorrower()` |
| `POST /api/stress-test` | Portfolio Analytics stress panel | mock slider math |
| `GET /api/model/metrics` | Model Performance cards | `MODEL_METRICS` |
| `GET /api/model/roc-curve` | Model Performance ROC chart | `ROC_CURVE` |
| `GET /api/model/confusion-matrix` | Model Performance confusion grid | `CONFUSION_MATRIX` |
| `GET /api/model/calibration` | Model Performance calibration plot | `CALIBRATION` |
| `GET /api/model/summary` | (new) model card panel | — |

Request/response bodies use **camelCase** keys (via a Pydantic
`alias_generator`) so they match `src/data/portfolio.ts` and
`src/lib/scoring.ts` exactly — you're renaming fetch calls, not rewriting
types.

### Example: score a borrower

```bash
curl -X POST http://localhost:8000/api/score \
  -H "Content-Type: application/json" \
  -d '{
    "income": 72000,
    "loanAmount": 48000,
    "creditUtilization": 46,
    "dti": 31,
    "creditHistory": 6,
    "openAccounts": 7,
    "employmentLength": 4
  }'
```

## Frontend wiring (already done)

`src/lib/api.ts` is a typed fetch client for every endpoint above. All four
pages (`Overview`, `Risk Scoring`, `Portfolio Analytics`, `Model
Performance`) use `@tanstack/react-query`'s `useQuery` / `useMutation`
against it — nothing in the UI reads `src/data/portfolio.ts` or
`src/lib/scoring.ts`'s `scoreBorrower()` anymore (those files are left in
place for their type definitions and as a reference for the original mock
logic). Each page shows a spinner while loading and a retry panel — with a
hint to check the backend is running — if a request fails.

The Portfolio Analytics stress-test panel debounces slider input 300ms
before calling `POST /api/stress-test`, so dragging a slider doesn't fire a
request per pixel.

Set `VITE_API_BASE_URL` in a `.env.local` at the frontend root (see
`.env.example`) if the backend isn't on `http://localhost:8000`, and update
CORS origins in `backend/app/config.py` if you deploy the two separately.

All currency figures display in **INR (₹)** — see `src/lib/format.ts`
(`inr`, `compactInr`, using Lakh/Crore compact notation). The underlying
numbers are unchanged; only the display symbol/grouping changed, so treat
the loan amounts as rupee figures going forward if you touch the ML
dataset ranges in `app/ml/dataset.py`.

## Retraining on real data

Replace `build_training_frame()` in `app/ml/dataset.py` with a loader that
returns a DataFrame containing the same 8 feature columns
(`FEATURE_COLUMNS`) plus a binary `default` column, then re-run
`python -m app.ml.train`. Everything else — API, SHAP explainability,
metrics — works unchanged against the new model.
